# LampCode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A privacy-first, account-free desktop AI coding agent (Tauri 2, Windows + Linux) that pools free/cheap model providers, plus a static marketing site.

**Architecture:** All logic that touches keys, network, files or processes lives in a modular Rust backend (`providers/`, `agent/`, `tools/`, `security/`, `storage/`, `mcp/`, `pty/`). The React frontend is a thin view that talks to Rust only through `tauri-specta`-generated typed commands and events and never sees a full key. Every outbound request passes one choke point (`security::net::GuardedClient`) that enforces the allowlist and redaction.

**Tech Stack:** Tauri 2, Rust (tokio, reqwest+rustls, serde, sqlx/SQLite, keyring, age, portable-pty, ignore, grep-searcher, similar, tauri-specta), React + TypeScript + Vite + Tailwind, xterm.js, CodeMirror 6, Vitest, Playwright, Astro (website), pnpm workspaces.

**Spec:** `LAMPCODE_PROMPT.md` (repo root). Section numbers below (§0.3, §2.8 ...) refer to it.

## Global Constraints

- §0 privacy rules override every feature. If a task conflicts with §0, the task changes, not the rule.
- No account, no LampCode server, no telemetry/analytics/crash upload. Crash logs local only, redacted.
- Keys: OS keychain via `keyring`; fallback `age`-encrypted file with user passphrase. Never plaintext in config, logs, sessions, crash dumps, localStorage. Frontend gets `sk-...last4` previews only.
- Env vars override saved keys (`OPENROUTER_API_KEY`, `GROQ_API_KEY`, `NVIDIA_API_KEY`, `GEMINI_API_KEY`, and each preset's `key_env`).
- One `redact()` function, used on every log line, UI error, and export.
- Outbound connections only to hosts derived from configured providers + MCP servers + enabled web search (+ per-tool approved hosts, scoped to that tool's process).
- Updates opt-in, asked once on first launch, minisign-verified.
- Tool output is wrapped as untrusted data in prompts; approval cards show the real command/diff.
- Rename point: app name lives only in `app/app.config.ts` + `app/src-tauri/tauri.conf.json`.
- Provider presets: base URL, env var, free-tier notes come from official docs with `docs_url` + `checked` date. Unconfirmed ones go to "Unverified providers" below, never guessed.
- Never open `~/.scoutcode/` or any ScoutCode config/keys. Respect ScoutCode guest limits.
- Copied MIT code keeps its notice in `THIRD_PARTY_NOTICES.md` + header comment. Prefer rewriting.
- No dependency that phones home; every added crate/npm package gets checked and listed in "Dependency audit" below.
- No `TODO: implement` stubs in a finished milestone. Out-of-scope items go in this file.
- Each milestone ends with: build green, tests green, commit, short summary to the user. Never move on with a broken build.
- Website: nothing copied from `reference/scoutcode-home.html` (code, copy, palette `#f5a524` family, logo, section titles, layout proportions). `reference/` is gitignored and never served.
- License: MIT, Copyright (c) 2026 Lamp Studios.

## Review Focus

Inputs the spec implies but doesn't spell out, most likely to bite first. Each has a test in the owning task.

1. **Non-UTF-8 / binary / huge files** in `read_file`, `grep`, diffs: must return a clean "binary file, N bytes" or truncated result, never panic or flood context. Test: `tools::fs::tests::read_binary_file_is_summarized` and `read_file_over_cap_is_truncated` (Task 3.2).
2. **Path tricks escaping the guard**: `..`, symlinks out of the project, Windows `\\?\`, case variants (`.ENV`, `ID_RSA`), 8.3 short names. Test: `security::guard::tests::guard_blocks_case_and_symlink_variants` (Task 3.1).
3. **Malformed streaming**: SSE chunks split mid-JSON, tool-call arguments delivered across many deltas, provider closing stream without `[DONE]`. Test: `providers::sse::tests::split_chunks_reassemble` and `stream_eof_without_done_finishes_turn` (Task 2.2).
4. **Keychain unavailable mid-session** (Secret Service locked / not running on Linux): app must fall back or prompt, never write plaintext. Test: `security::keys::tests::locked_keychain_falls_back_to_age` (Task 1.4).
5. **Cancel during a running PTY command or partway through a multi-file edit**: process tree killed, checkpoint still consistent, `/undo` still works. Test: `agent::tests::cancel_mid_tool_kills_process_and_keeps_checkpoint` (Task 4.3).

## Decisions I made (flag any you want changed)

- **Execution:** native (in-session) for every milestone except 2.5, which runs subagent-driven. User decision, 2026-11-19.
- **Website design** is pinned in `website/DESIGN.md` (written ahead of milestone 9). Task 9.1 becomes "re-check DESIGN.md against the real app screenshots".

- **pnpm workspaces** (`app`, `website`). Bun is installed too, but pnpm has the most predictable Tauri + Astro story.
- **Providers as one JSON file per preset** in `resources/providers/`. A "provider pack" is literally the same file format, so user packs and built-ins share one loader. `providers.json` from the spec is generated at build time as the merged list (the website reads that).
- **Rust owns the agent loop and streaming.** The frontend subscribes to a `SessionEvent` stream (text delta, tool call, approval request, model switch, usage). No business logic in TS.
- **Shadow checkpoints** use `gix` (pure-Rust git) with a bare repo per project under app data, so it works without `git` installed.
- **Age fallback** passphrase is held in memory only (zeroized), asked once per app launch.
- **JSON-in-text tool protocol** for models without native tools: XML-ish `<tool_call>{json}</tool_call>` blocks, parsed by a tolerant parser, documented in the system prompt.
- **Windows sandbox for custom tools**: Job Object (kill-on-close, no breakaway, memory + CPU caps) via the `windows` crate. Honestly labeled "restricted, not sandboxed" since it doesn't limit fs/network.
- **Website deploy**: GitHub Pages via Actions; custom domain in `website/site.config.ts`.
